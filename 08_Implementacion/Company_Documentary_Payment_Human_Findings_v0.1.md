# Company Documentary Payment Human Findings v0.1

New reviews v08 allow explicit local findings for the existing documentary payment review inventory: global operation correspondence, terms and listed duplication, and per-binding association, amount, currency, due date and support consistency. Each submitted finding supplies outcome, note and reviewer. Positive findings require a conserved documentary locator; per-installment locators must be part of the exact examined binding. No bulk confirmation or implicit findings are generated.

The service uses build_documentary_payment_human_review and preserves its canonical DOC-PAY-REVIEW-01/v0.1 payload. It rebuilds the conserved capture through public factories using the real read-only parameter Centre ports, original financial inputs and conserved source bytes, then requires identical package/capture fingerprints. It does not instantiate opaque classes or invent imported parameter configurations. If the original Centre configuration cannot be reproduced exactly, recording fails. No financial or rule engine is run by the recording endpoint.

Append-only company_payment_human_review rows keep capture/dataset/proposal scope, revision, canonical fingerprint and payload. A correction replaces the matching finding in a new cumulative review with previous_review_ref; earlier revisions remain stored. Optimistic revision and BEGIN IMMEDIATE prevent lost updates. Current company reports capture the latest summary for their exact capture; old printable reports remain unchanged.

Counts distinguish confirmed, not confirmed, discrepancies and omitted controls. A negative finding has been examined but is not confirmation. Zero omitted controls does not mean all outcomes are positive, nor certify required calendar coverage, completeness, admission or viability. Identity is a local declaration, not enterprise authentication. Evidence upgrades remain NOT_PERFORMED and operational path FORBIDDEN. The old capture control count is labelled pending at capture time to distinguish it from subsequent review results.

Tests cover canonical payload and pending controls, correction/history/stale revisions, exact-support requirements, unsupported outcomes, negative findings, frozen printing, source deletion, all-positive controls without evidence promotion, wrong scope and missing captures. The endpoint uses existing Host/token checks; full CI checks Python, JavaScript syntax and SQL Server contracts. Visual verification remains pending while the local environment is offline.
