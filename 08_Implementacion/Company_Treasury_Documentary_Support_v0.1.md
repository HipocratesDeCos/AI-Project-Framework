# Company Treasury Documentary Support v0.1

Company review v11 can bind an explicit treasury declaration to a uniquely conserved document: record reference, local responsible person, documentary company, amount, currency, economic date and document/page/section. The service uses FIN-TREASURY-SUPPORT-01/v0.1 without changing the financial snapshot or evidence states.

The original financial quality preparation is reproduced through public factories and real read-only Centre ports. The selected preparation, calendar and human review must still match their exact dependency fingerprints. Missing or stale material blocks saving.

A chosen support already present in the payment capture uses its conserved original bytes. A separate treasury document must exist in the proposal's source inventory, with current bytes matching its saved SHA256. Changed, foreign or missing documents are rejected. No filename or source material is invented.

The canonical service records technical amount/currency/economic-date comparisons, including mismatches. No TreasuryObservation is manufactured: all six contextual controls (source correspondence, cutoff, amount support, availability, restrictions and sufficiency) remain pending. Local identity is not authenticated. These comparisons do not determine financial quality, QTG admission or purchase viability.

Append-only company_treasury_documentary_support rows conserve exact payloads and revisions. Old reports remain frozen; new reports mark earlier support when the financial preparation changes. Commercial drafts exclude internal support records. The UI labels comparisons as technical and shows the declared values separately from the package reference. The first form binds one selected document; broader documentary sufficiency remains unestablished.

Tests cover canonical bytes/fingerprint binding, pending controls, discrepancies without snapshot replacement, explicit inputs, scope/stale revisions, source deletion for captured material, changed separate-source rejection, history, prior-material status, frozen printing and HTTP token/route checks. Existing Python, embedded JavaScript and SQL Server checks remain required. Browser visual verification remains pending because the cloud browser cannot reach the loopback-only server; no alternate network exposure is introduced.

Local validation completed: 22 focused checks and the full pytest suite (2,701 passed). Visual QA remains pending.
